### [Post Body]

Hey r/LocalLLaMA,

With the recent launch of Claude Code, the power of terminal-based autonomous AI agents is undeniable. However, many developers prefer keeping their workspaces isolated, free of continuous cloud costs, and completely private.

Over the past two weeks, I designed and open-sourced **Agent Kharwal (Apex Lite)**—a fully self-hosted, offline-ready autonomous developer agent written in Dart that runs directly in your command line.

It can be powered entirely locally by **Gemma 4 (2B)** via **LiteRT-LM** (for Android local execution) or **Ollama / llama.cpp** (for headless Linux/macOS CLI runs), as well as cloud-fallback APIs (Gemini, Groq, OpenRouter).

Here is the engineering deep-dive on how we structured the runtime:

### 1. TerminalForge: The ANSI TUI
Running interactive CLI agents requires high readability. I built `TerminalForge`, a luxury ANSI-rendered terminal engine that splits the stdout view into three components:
* **The Thought Console:** Real-time streaming of the model's internal monologues and reasoning steps.
* **The Dashboard:** Dynamic status counters detailing the active model, current provider health, active tasks, and latency metrics.
* **Inline Tool Cards:** Expanding and folding ANSI blocks showing the raw command input, execution logs, and sandbox results.

### 2. 35+ Integrated Developer Tools
Unlike simple command wrappers, Kharwal integrates a full agentic protocol:
* **Workspace Mutation:** Sandboxed relative patch editors (`FileEditTool`), regex search (`GrepTool`), and recursive file indexers.
* **Model Context Protocol (MCP):** Dynamic schema loading and resource reading from self-hosted MCP servers.
* **Subprocess Management:** Deep `SpectralOps` shell running a `BudgetWatchdog` that reaps runaway processes and orphans recursively (preventing memory leaks).
* **Multi-Agent & Schedulers:** Native cron tool integration to schedule background workspace health checks, multi-agent communication networks, and git worktrees manager.

### 3. Smart Waterfall Failover & Provider Health
To avoid interruption during heavy development tasks, the CLI features a live failover queue. The `ProviderHealthRegistry` monitors API response states (classifying failures into RateLimits, NetworkTimeouts, or AuthErrors). If your primary provider fails, it triggers a "Smart Smart Smart Smart Failover," hot-swapping to Ollama or a secondary API mid-loop without losing context history.

### 4. Enterprise Sandboxing & The Secret Guard
* **Chowkidar (Secret Redactor):** Scans prompts recursively and dynamically redacts private keys or API tokens prior to payload generation.
* **PathJailer:** Normalizes paths and validates them against the sandboxed workspace, resolving symlinks to prevent directory traversal injections.

### 5. Self-Correction (AetherCore Heartbeat)
When running small 2B models locally, tag formatting stutters are common. AetherCore utilizes a custom "Withholding Pattern" — the compiler catches malformed XML tokens mid-stream, silently injects corrective instructions into the LLM context, and retries the turn behind the scenes, outputting clean tool cards to the console once resolved.
